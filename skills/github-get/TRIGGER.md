# GitHub-Get Skill 触发条件

## 🎯 自动触发条件

### 1. 包含 GitHub 链接
当用户消息中包含 GitHub 项目链接时自动触发：

```
✅ https://github.com/{owner}/{repo}
✅ https://github.com/{owner}/{repo}.git
✅ github.com/{owner}/{repo}
```

**示例：**
```
用户：https://github.com/microsoft/playwright-mcp
用户：看看这个 https://github.com/tinyhumansai/openhuman
```

### 2. 分析请求关键词
当用户消息包含以下关键词时触发：

```
✅ "分析" + "项目/仓库"
✅ "解析" + "项目/仓库"
✅ "看看" + "项目/仓库"
✅ "了解" + "项目/仓库"
✅ "研究" + "项目/仓库"
```

**示例：**
```
用户：帮我分析这个项目
用户：解析一下这个仓库
用户：看看这个项目是做什么的
```

### 3. 同样要求模式
当用户引用之前的分析模式时触发：

```
✅ "按照同样的要求处理"
✅ "同样的要求"
✅ "跟之前一样"
✅ "照着之前的格式"
```

**示例：**
```
用户：按照同样的要求处理 https://github.com/xxx/xxx
用户：同样的要求 https://github.com/xxx/xxx
```

### 4. 批量处理请求
当用户提供多个链接或要求批量处理时触发：

```
✅ "这几个你逐个处理"
✅ "逐个按照要求处理"
✅ 多个 GitHub 链接
```

**示例：**
```
用户：这几个你逐个逐个按照要求处理！OK？
https://github.com/xxx/xxx
https://github.com/yyy/yyy
https://github.com/zzz/zzz
```

## 🚫 不触发的情况

以下情况 **不会** 触发 GitHub-Get Skill：

```
❌ 用户只是提到 GitHub 但没有链接
❌ 用户讨论 GitHub 本身（不是分析项目）
❌ 用户分享非 GitHub 链接
❌ 用户只是复制粘贴代码（不是项目链接）
```

**示例（不触发）：**
```
用户：我喜欢用 GitHub
用户：GitHub 是一个很好的平台
用户：这是我的代码 [粘贴代码]
```

## 🔄 重复项目处理

**重要：当用户发送已分析过的项目链接时，不会重新分析！**

### 处理流程

```
用户发送 GitHub 链接
        ↓
检测是否已分析过
        ↓
┌───────┴───────┐
│               │
已分析过        未分析过
│               │
↓               ↓
跳过分析        正常分析
↓               ↓
提示用户        生成文件
↓               ↓
输出已有结果    存入记忆
↓               ↓
询问是否更新    输出报告
```

### 输出示例（已分析过的项目）

```
⚠️ 该项目已于 2026-06-06 分析过，直接输出已有结果：

## 🎯 Playwright MCP 项目速览

| 字段 | 内容 |
|------|------|
| **项目名称** | Playwright MCP |
| **项目地址** | https://github.com/microsoft/playwright-mcp |
| **核心定位** | 基于 Playwright 的 MCP 浏览器自动化服务器 |
| **分析时间** | 2026-06-06 |

📄 详细分析：14-Playwright-MCP.md
🧠 记忆索引：2026-06-06-playwright-mcp-project.md

---

是否需要重新解析或更新？
- 回复 **"更新"** 或 **"重新解析"** → 我会重新获取最新信息并覆盖原有结果
- 回复 **"查看"** → 我会输出完整的详细分析内容
- 回复 **"跳过"** 或直接忽略 → 不做任何操作
```

### 用户选择更新时

```
用户：更新
或
用户：重新解析

AI：正在重新分析 Playwright MCP...

[执行完整分析流程]

✅ 已更新！（上次分析：2026-06-06，本次更新：2026-06-07）
```

## 🔄 触发后的流程

当触发 GitHub-Get Skill 时，会执行以下流程：

```
1. 识别 GitHub 链接
   └─ 提取 owner 和 repo

2. 获取项目信息
   └─ README → GitHub API → 备选方案

3. 分析项目
   └─ 提取核心信息 → 生成分析报告

4. 存储记忆
   └─ 创建 MD 文件 → 更新索引 → 验证写入

5. 输出结果
   └─ 项目速览 → 文件路径 → 更新统计
```

---

## 📊 输出格式

触发后会输出：

```
✅ 已创建的文件（详细分析、记忆索引、总索引）
✅ 项目速览（名称、地址、定位、亮点）
✅ 安装方式
✅ 项目库统计（现在有多少个项目）
```
