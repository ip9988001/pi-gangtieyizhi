### 阶段一：信息获取

```bash
# 步骤1: 尝试获取 README（优先 main 分支）
curl -s -L --connect-timeout 20 "https://raw.githubusercontent.com/{owner}/{repo}/main/README.md"

# 步骤2: 如果失败，尝试 master 分支
curl -s -L --connect-timeout 20 "https://raw.githubusercontent.com/{owner}/{repo}/master/README.md"

# 步骤3: 如果仍然失败，通过 GitHub API 获取描述
curl -s "https://api.github.com/repos/{owner}/{repo}" | grep '"description"'

# 步骤4: 获取文件树了解项目结构
curl -s "https://api.github.com/repos/{owner}/{repo}/git/trees/main?recursive=1"

# 步骤5: 尝试获取中文 README（如果有的话）
curl -s -L --connect-timeout 20 "https://raw.githubusercontent.com/{owner}/{repo}/main/README.zh-CN.md"
```

### 阶段二：信息提取

## 🔧 核心规则

### 规则1：信息获取优先级
```
1. README.md（main 分支）
2. README.md（master 分支）
3. README.zh-CN.md（中文版）
4. GitHub API 描述
5. package.json / pyproject.toml
```

### 规则2：文件命名规范
```
详细分析：{序号}-{项目名称}.md（如 22-OpenHuman.md）
记忆索引：{日期}-{project-name}-project.md
总索引：{日期}-seven-projects-index.md（沿用原名，内容更新）
```

### 规则3：内容质量标准
```
✅ 每个项目必须包含 7 个标准章节
✅ 文件大小 > 3KB（内容充实）
✅ 二级标题数量 >= 7 个
✅ 包含代码示例或命令
✅ 包含适用场景
```

### 规则4：记忆系统写入
```
✅ 使用 write 工具直接写入 ~/.pi/agent/memory/l1/
✅ 每个项目单独一个索引文件
✅ 更新总索引文件
✅ 使用 recall_memory 验证写入成功
```

### 规则5：错误处理
```
⚠️ 网络超时 → 重试或使用 GitHub API
⚠️ 404 错误 → 尝试其他分支
⚠️ 信息不完整 → 标注"待补充"并尝试补充
⚠️ 文件太小 → 补充内容
```

## ⚠️ 注意事项

1. **网络问题**：如果 GitHub 访问失败，尝试多种获取方式
2. **信息不完整**：如果 README 信息不足，尝试获取其他文件（package.json 等）
3. **中文优先**：如果项目有中文 README，优先使用中文版本
4. **序号管理**：确保项目序号连续，不重复
5. **记忆验证**：每次写入记忆后都要验证
