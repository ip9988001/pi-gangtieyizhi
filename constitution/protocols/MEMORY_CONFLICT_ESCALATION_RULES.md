# 记忆冲突升级链规则

## 冲突定义

记忆冲突是指两个或多个记忆条目之间存在矛盾、不一致或互相否定的情况。

## 冲突类型

### 1. 事实冲突
- **定义**: 两个条目对同一事实有不同描述
- **示例**: 条目A说"端口是8080"，条目B说"端口是3000"

### 2. 偏好冲突
- **定义**: 用户在不同时间表达了相反的偏好
- **示例**: 之前说"喜欢React"，后来又说"喜欢Vue"

### 3. 状态冲突
- **定义**: 条目状态不一致
- **示例**: 条目A标记为"active"，但条目B标记为"deprecated"

## 冲突检测

### 自动检测
1. **写入时检测**: 新条目写入时与现有条目对比
2. **检索时检测**: 检索结果中发现矛盾条目
3. **定期扫描**: 定期扫描可能的冲突

### 手动检测
1. **用户报告**: 用户发现矛盾
2. **系统提醒**: 系统发现可疑冲突

## 冲突升级链

### 第一级：标记风险
- **条件**: 发现潜在冲突，但不确定
- **操作**: 在条目中添加"risk"标记
- **通知**: 无通知，仅记录

### 第二级：标记冲突
- **条件**: 确认存在冲突
- **操作**: 将state改为"conflict"
- **通知**: 提醒用户存在冲突

### 第三级：升级裁决
- **条件**: 冲突无法自动解决
- **操作**: 升级到裁决系统（包13）
- **通知**: 请求裁决

### 第四级：裁决完成
- **条件**: 裁决系统做出决定
- **操作**: 更新条目状态，记录裁决结果
- **通知**: 通知用户裁决结果

## 冲突处理流程

```
发现冲突
    ↓
标记风险 → 继续观察
    ↓
确认冲突 → 标记state="conflict"
    ↓
尝试自动解决 → 成功? → 更新条目
    ↓
升级裁决 → 裁决系统处理
    ↓
裁决完成 → 更新条目，记录结果
```

## 自动解决规则

### 可自动解决
1. **时间冲突**: 以最新条目为准
2. **来源冲突**: 以更可靠来源为准
3. **状态冲突**: 以active状态为准

### 需要裁决
1. **事实冲突**: 无法判断哪个正确
2. **偏好冲突**: 用户偏好不明确
3. **重要冲突**: 影响系统行为的冲突

## 冲突记录

### 冲突日志
- 记录冲突双方、发现时间、处理结果
- 用于追溯和审计

### 冲突统计
- 统计冲突频率、类型、解决方式
- 识别容易产生冲突的领域

## 注意事项

1. **冲突不能静默覆盖**: 必须记录和处理
2. **保留冲突证据**: 裁决前保留冲突双方
3. **记录裁决结果**: 裁决完成后记录结果
4. **允许冲突存在**: 某些冲突可能无法完全解决
