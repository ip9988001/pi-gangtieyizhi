# 检索命中回写规则

## 回写定义

检索命中回写是recall命中后，将使用信号回流到记忆层的机制。

## 最小回写字段

### 1. last_accessed (最后访问时间)
- **类型**: string (ISO 8601)
- **说明**: 条目最后一次被访问的时间
- **更新时机**: 每次recall命中后
- **更新方式**: 更新为当前时间

### 2. access_count (访问次数)
- **类型**: number
- **说明**: 条目被访问的次数
- **更新时机**: 每次recall命中后
- **更新方式**: 递增1

## 不应回写到条目正文的信号

### 1. 命中历史
- **说明**: 历次recall命中的记录
- **去向**: 进入事件账本
- **原因**: 命中历史会膨胀条目正文

### 2. 检索上下文
- **说明**: recall命中时的查询上下文
- **去向**: 进入事件账本
- **原因**: 检索上下文是临时性的

### 3. 检索层级
- **说明**: recall命中的检索层级（S1/S2/S3）
- **去向**: 进入事件账本
- **原因**: 检索层级是元数据，不是正文内容

## 回写流程

```
recall命中
    ↓
提取目标条目
    ↓
更新last_accessed → 当前时间
    ↓
更新access_count → 递增1
    ↓
记录命中信号到事件账本
    ↓
回写完成
```

## 回写规则

### 规则1: 最小回写
- **说明**: 只回写last_accessed和access_count
- **原因**: 最小回写保持条目简洁
- **例外**: 不回写其他字段

### 规则2: 信号进账本
- **说明**: 命中信号进入事件账本，不进条目正文
- **原因**: 事件账本适合追加式留痕
- **位置**: `~/.pi/agent/memory/agent/system/RECALL_SIGNAL_LEDGER.jsonl`

### 规则3: 不膨胀条目
- **说明**: 不将命中历史塞回条目正文
- **原因**: 膨胀的条目难以维护
- **方式**: 保持条目正文简洁

## 回写记录

### 回写日志
- 记录每次回写的条目、时间、字段
- 用于追溯和审计

### 回写统计
- 统计回写频率、条目访问频率
- 识别高频访问条目

## 注意事项

1. **最小回写**: 只回写必要字段，不膨胀条目
2. **信号进账本**: 命中信号进入事件账本，不进条目正文
3. **记录回写**: 所有回写应记录，便于追溯
