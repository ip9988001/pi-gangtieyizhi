# 记忆-检索字段契约

## 契约定义

记忆-检索字段契约定义了记忆条目在写入时必须包含的字段，以供recall检索使用。

## 条目层必要字段

### 1. keywords (关键词)
- **类型**: string[]
- **说明**: 用于检索的关键词
- **示例**: ["微服务", "重启", "半夜", "事故"]

### 2. aliases (别名)
- **类型**: string[]
- **说明**: 用于中文同义词匹配的别名
- **示例**: ["夜间重启教训", "凌晨操作禁忌"]

### 3. summary (摘要)
- **类型**: string
- **说明**: 条目的简短摘要，用于快速预览
- **示例**: "永远不要在半夜2点后执行微服务重启"

### 4. state (状态)
- **类型**: string
- **说明**: 条目的当前状态，用于过滤
- **示例**: "active"

### 5. read_hint (读取提示)
- **类型**: string
- **说明**: 读取该条目时的提示信息
- **示例**: "运维人员必读，避免夜间操作事故"

### 6. anchor_refs (锚点引用)
- **类型**: string[]
- **说明**: 条目的来源锚点，用于溯源
- **示例**: ["agent/lessons/night-restart-lesson.md"]

## 条目层可选增强字段

### 1. last_accessed (最后访问时间)
- **类型**: string (ISO 8601)
- **说明**: 条目最后一次被访问的时间
- **示例**: "2026-06-03T10:30:00Z"

### 2. access_count (访问次数)
- **类型**: number
- **说明**: 条目被访问的次数
- **示例**: 8

### 3. confidence (置信度)
- **类型**: number (0-1)
- **说明**: 条目的可信程度
- **示例**: 0.98

### 4. freshness (新鲜度)
- **类型**: string
- **说明**: 条目的新鲜程度
- **示例**: "fresh"

## 字段附着规则

### 字段应直接附着在条目本身
- **原因**: 条目是真相源，字段应与条目一起存储
- **方式**: 在条目文件的元数据部分定义字段
- **示例**:
```yaml
summary: "永远不要在半夜2点后执行微服务重启"
keywords: ["微服务", "重启", "半夜", "事故"]
aliases: ["夜间重启教训", "凌晨操作禁忌"]
state: "active"
read_hint: "运维人员必读，避免夜间操作事故"
anchor_refs: ["agent/lessons/night-restart-lesson.md"]
```

### 字段不应集中塞进大总表
- **原因**: 大总表难以维护，容易产生不一致
- **方式**: 每个条目自带字段，不依赖外部总表
- **例外**: INDEX等导航投影可汇总部分字段

## 条目类型要求

### L3长期记忆
- **必须包含**: 所有6个必要字段
- **建议包含**: 所有可选增强字段
- **说明**: 长期记忆是最重要的条目，必须完整

### L2候选
- **必须包含**: keywords、summary、state
- **建议包含**: aliases、read_hint、anchor_refs
- **说明**: 候选条目正在验证中，字段可逐步完善

### L1碎片
- **必须包含**: summary
- **建议包含**: keywords、state
- **说明**: 碎片条目是临时性的，字段要求最低

## 契约检查

### 写入前检查
- 在将条目写入L2/L3前，检查是否符合契约
- 不符合契约的条目，补充字段后再写入

### 定期检查
- 定期扫描现有条目，检查是否符合契约
- 不符合契约的条目，标记并提醒补充

## 注意事项

1. **条目是真相源**: 字段应附着在条目本身，不依赖外部总表
2. **字段逐步完善**: L2候选可逐步完善字段，不必一次到位
3. **契约是最低要求**: 符合契约是最低要求，鼓励添加更多字段
