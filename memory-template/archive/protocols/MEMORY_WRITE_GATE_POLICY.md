# 记忆写入闸门政策

## 写入闸门定义

写入闸门是记忆条目从低层级晋升到高层级前必须通过的检查机制，用于防止不可信、不稳定、未验证的内容进入长期记忆。

## L1 → L2 闸门

### 检查项
1. **锚点检查**: 条目是否有来源锚点
2. **频次检查**: 条目是否出现2次以上
3. **影响度检查**: 条目是否对用户行为有影响
4. **稳定性检查**: 条目是否跨会话稳定

### 通过条件
- 至少满足3项检查
- 无冲突标记
- 置信度 ≥ 0.5

### 不通过处理
- 留在L1碎片
- 继续观察
- 等待更多证据

## L2 → L3 闸门

### 检查项
1. **锚点检查**: 条目是否有至少1个锚点
2. **频次检查**: 条目是否出现3次以上
3. **影响度检查**: 条目是否对用户行为有持续影响
4. **稳定性检查**: 条目是否跨会话稳定
5. **验证检查**: 条目是否被验证过

### 通过条件
- 满足所有5项检查
- 无冲突标记
- 置信度 ≥ 0.7
- 新鲜度为"fresh"

### 不通过处理
- 留在L2候选
- 继续验证
- 等待晋升条件

## 特殊规则

### 日志类内容
- 只允许留在L1或日志区
- 不进入L2/L3
- 用于短期参考

### 临时性内容
- 只允许留在L1
- 有明确过期时间
- 过期后自动清理

### 冲突内容
- 标记state为"conflict"
- 升级到裁决系统
- 裁决前不允许晋升

## 写入闸门检查流程

```
输入: 记忆条目 + 目标层级
      ↓
检查锚点 → 无锚点? → 拒绝写入
      ↓
检查频次 → 频次不足? → 留在当前层级
      ↓
检查影响度 → 影响度低? → 留在当前层级
      ↓
检查稳定性 → 不稳定? → 留在当前层级
      ↓
检查置信度 → 置信度低? → 降级写入
      ↓
检查新鲜度 → 不新鲜? → 需要验证
      ↓
检查状态 → 有冲突? → 升级处理
      ↓
通过闸门 → 允许写入目标层级
```

## 注意事项

1. **闸门是抗失真机制**: 不是额外官僚流程
2. **不要跳过闸门**: 即使内容看起来很有价值
3. **允许降级写入**: 不满足高层级要求时，可降级写入低层级
4. **记录检查结果**: 所有检查结果应记录，便于追溯
