# 查询路由政策

## 查询路由定义

查询路由是在进入recall（S1/S2/S3）之前，先判断问题类型，确定默认检索路径的机制。

## 查询类型分类

### 1. 状态查询 (status)
- **特征**: 查询当前状态、配置、设置
- **关键词**: 状态、status、当前、现在
- **默认路径**: S1（快速检索）
- **说明**: 状态类查询通常有明确答案，快速检索即可

### 2. 偏好查询 (preference)
- **特征**: 查询用户偏好、习惯、喜好
- **关键词**: 偏好、喜欢、preference、总是
- **默认路径**: S1（快速检索）
- **说明**: 偏好类查询通常在偏好文件中

### 3. 决策查询 (decision)
- **特征**: 查询历史决策、选择依据
- **关键词**: 决策、决定、选择、decision
- **默认路径**: S2（语义检索）
- **说明**: 决策类查询需要语义理解

### 4. 案例查询 (case)
- **特征**: 查询历史案例、教训、经验
- **关键词**: 案例、教训、经验、case
- **默认路径**: S2（语义检索）
- **说明**: 案例类查询需要语义匹配

### 5. 时间线查询 (timeline)
- **特征**: 查询历史时间线、事件顺序
- **关键词**: 时间、历史、之前、timeline
- **默认路径**: S2（语义检索）
- **说明**: 时间线查询需要时间维度检索

### 6. 模糊回忆 (fuzzy)
- **特征**: 模糊记忆、不确定的查询
- **关键词**: 其他所有查询
- **默认路径**: S2（语义检索）
- **说明**: 模糊回忆需要语义理解

## 路由升级规则

### S1 → S2 升级
- **条件**: S1检索结果不足3个，或结果质量低
- **操作**: 升级到S2语义检索
- **说明**: 快速检索不足时，升级到语义检索

### S2 → S3 升级
- **条件**: S2检索结果不足5个，或问题复杂
- **操作**: 升级到S3深度检索
- **说明**: 语义检索不足时，升级到深度检索

## 路由记录

### 路由日志
- 记录每次查询的路由结果
- 用于追溯和优化

### 路由统计
- 统计各类型查询频率
- 识别路由优化点

## 注意事项

1. **路由是前置判断**: 不是替代recall，而是优化recall入口
2. **允许升级**: 默认路径不是固定路径，允许根据实际情况升级
3. **记录路由**: 所有路由应记录，便于追溯
