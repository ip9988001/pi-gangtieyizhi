# 钢铁意志·PI版 - L1写入协议

## 更新时间
2026-06-02 19:15:28

## 这是什么
这是钢铁意志·PI版的L1写入协议，定义了哪些内容必须先进入L1碎片缓存区。

## 哪些内容必须先进入 L1
1. 用户明确表达的偏好
2. 关键动作的执行结果
3. 失败和错误的记录
4. 新决策和边界变化
5. 阻塞和回滚事件
6. 人工确认点

## ordinary work 默认写到哪里
1. `memory/YYYY-MM-DD.md` - 每日日志
2. `NOW.md` - 当前状态
3. `stages/XX-包名-result.md` - 执行结果

## 治理任务额外写到哪里
1. `system/governance/<task_id>/05_execution_log.md` - 治理日志
2. `system/ledger.json` - 操作账本
3. `memory/YYYY-MM-DD.md` - 每日日志（同步更新）

## 什么情况下只写日志，不直接做候选晋升
1. 事实尚未验证
2. 只发生过一次
3. 需要进一步观察
4. 证据不足

## L1写入流程
```
事实发生
  ↓
判断是否需要记录
  ├─ 是 → 写入L1
  └─ 否 → 跳过
  ↓
写入每日日志
  ↓
判断是否需要候选晋升
  ├─ 是 → 标记"待后续进入L2初筛"
  └─ 否 → 保留在L1
```

## L1写入格式
```markdown
## [时间] [事件类型]

**事实**：[描述发生了什么]

**影响**：[描述对系统的影响]

**决策**：[描述做出的决策]

**状态**：[已完成/进行中/待确认]
```
