# 记忆新鲜度与验证规则

## 新鲜度定义

新鲜度用于衡量记忆条目的时效性，帮助判断条目是否仍然可信。

## 新鲜度分档

### fresh (新鲜)
- **定义**: 最近验证过，可信任
- **条件**: last_verified在7天内
- **处理**: 可直接使用，可注入

### stale (过时)
- **定义**: 较久未验证，需要验证
- **条件**: last_verified在7-30天内
- **处理**: 使用前建议验证，可参考但不宜默认注入

### unverified (未验证)
- **定义**: 从未验证，谨慎使用
- **条件**: 无last_verified或超过30天
- **处理**: 仅作参考，不建议使用

## 验证时机

### 自动验证
1. **条目被成功使用**: 使用成功后自动更新last_verified
2. **条目被确认正确**: 用户确认后自动更新
3. **定期验证**: 长期未访问的条目定期提醒验证

### 手动验证
1. **用户主动验证**: 用户明确表示"这个是对的"
2. **系统提醒验证**: 系统发现条目可能过时
3. **冲突解决后**: 冲突裁决完成后验证

## 验证更新规则

### 更新last_verified
- 条件: 条目被验证为正确
- 操作: 更新last_verified为当前时间
- 附带: 更新freshness为"fresh"

### 不更新last_verified
- 条件: 条目未被使用或验证
- 操作: 保持last_verified不变
- 附带: freshness可能降级

## 新鲜度降级规则

### fresh → stale
- 条件: last_verified超过7天
- 操作: freshness改为"stale"
- 通知: 提醒用户条目可能需要验证

### stale → unverified
- 条件: last_verified超过30天
- 操作: freshness改为"unverified"
- 通知: 提醒用户条目需要验证

## 验证记录

### 验证日志
- 记录每次验证的时间、结果、原因
- 用于追溯和审计

### 验证统计
- 统计条目验证频率
- 识别长期未验证的条目

## 注意事项

1. **不要忽略新鲜度**: 过时的条目可能不再准确
2. **定期验证**: 重要条目应定期验证
3. **允许降级**: 长期未验证的条目应降级
4. **记录验证**: 所有验证应记录，便于追溯
