# 读取预算控制规则

## 读取预算定义

读取预算控制是限制recall检索深度和结果数量的机制，用于避免过度读取，提高检索效率。

## 预算分档

### R0 (快速检索)
- **最大结果数**: 3
- **最大深度**: 1
- **适用场景**: 状态查询、偏好查询
- **说明**: 只检索最直接相关的条目

### R1 (语义检索)
- **最大结果数**: 5
- **最大深度**: 2
- **适用场景**: 决策查询、案例查询、时间线查询、模糊回忆
- **说明**: 进行语义理解，检索相关条目

### R2 (深度检索)
- **最大结果数**: 10
- **最大深度**: 3
- **适用场景**: 复杂问题、需要详细分析
- **说明**: 深度检索，覆盖更多相关条目

## 预算分配规则

### 默认预算
- **状态查询**: R0
- **偏好查询**: R0
- **决策查询**: R1
- **案例查询**: R1
- **时间线查询**: R1
- **模糊回忆**: R1

### 预算升级
- **条件**: 查询复杂度高，或R1结果不足
- **操作**: 升级到R2
- **限制**: 升级需要有明确理由

### 预算降级
- **条件**: 查询简单，或R0已足够
- **操作**: 保持R0
- **说明**: 简单查询不需要深度检索

## 预算控制流程

```
查询输入
    ↓
判断查询类型 → 确定默认预算
    ↓
执行检索 → 检查结果数量
    ↓
结果不足? → 升级预算
    ↓
结果充足? → 返回结果
    ↓
预算耗尽? → 返回"信息不足"
```

## 信息不足处理

### 什么时候返回"信息不足"
- **条件**: R2预算耗尽，结果仍不足
- **处理**: 返回"信息不足，建议补充查询"
- **说明**: 宁可返回信息不足，也不盲目深读

### 信息不足后的操作
1. **提示用户**: 告知用户信息不足
2. **建议补充**: 建议用户补充查询条件
3. **记录原因**: 记录信息不足的原因

## 预算记录

### 预算日志
- 记录每次查询的预算使用情况
- 用于追溯和优化

### 预算统计
- 统计各预算级别的使用频率
- 识别预算优化点

## 注意事项

1. **少读但更准**: 预算控制的目标是提高检索质量，不是减少检索
2. **允许升级**: 预算不是固定限制，允许根据实际情况升级
3. **记录预算**: 所有预算使用应记录，便于追溯
